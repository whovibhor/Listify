# Listify — API Design

Conventions are defined in ADR-012. OpenAPI is generated by FastAPI at `/api/openapi.json` and browsable at `/api/docs` (disabled when `APP_ENV=production`).

## Conventions

- Base path: `/api/v1`.
- JSON only. Request and response bodies use dedicated Pydantic schemas, never ORM models.
- Authentication (from M1): HttpOnly session cookie `listify_session`; unsafe methods also require the `X-CSRF-Token` header matching the `listify_csrf` cookie (ADR-004, ADR-006).
- Every response carries `X-Request-ID` (accepted from the client if it is ≤ 64 chars of `[A-Za-z0-9_-]`, otherwise generated).
- Errors, for every non-2xx status:

  ```json
  { "error": { "code": "validation_error", "message": "Request validation failed",
               "details": [{ "field": "title", "message": "Field required" }],
               "request_id": "3f2c…" } }
  ```

  | Status | `code` | When |
  |---|---|---|
  | 400 | `bad_request` | malformed request not covered by validation |
  | 401 | `unauthenticated` | missing/expired session |
  | 403 | `forbidden` | resource visible but action not permitted, or CSRF failure |
  | 404 | `not_found` | missing **or not visible to the caller** (avoids cross-tenant existence leaks) |
  | 409 | `conflict` | uniqueness or state conflict |
  | 413 | `payload_too_large` | request body over 1 MB, or a file over 10 MB |
  | 503 | `server_busy` | too many requests at once for 30 seconds; sent with `Retry-After` |
  | 422 | `validation_error` | schema validation failed |
  | 429 | `rate_limited` | rate limit exceeded |
  | 500 | `internal_error` | unexpected; no internals exposed, details only in server log |
  | 503 | — | `/health` only, returns the health body with `status: "degraded"` |

- Pagination: `page` (1-based), `page_size` (default 25, max 100) → `{ "items": [], "page": 1, "page_size": 25, "total": 0 }`.
- Sorting: `sort=field,-other`. Filtering: explicit, documented query parameters per endpoint.
- Timestamps in responses are ISO 8601 UTC with `Z`.
- Text input: names, titles and other single-line fields refuse line breaks and control characters. Descriptions, notes and reasons keep line breaks. Passwords are never altered.
- Dates on tasks and date filters must fall between 1900-01-01 and 2200-12-31.
- Creation limits per user per hour, answered with 429: 20 organizations, 100 departments, 1,000 tasks (including subtasks), 200 tags, 300 comments, 100 uploads, 200 update requests.
- `/api/v1` responses carry `Cache-Control: no-store`, a restrictive Content-Security-Policy, `X-Content-Type-Options`, `X-Frame-Options` and `Referrer-Policy`. Production adds HSTS.

### Reports (Phase 7)

Every number comes from `visible_tasks`, so a report can't count a task its reader couldn't open. `start` and `end` are dates in the organization's timezone: `end` defaults to today and `start` to 30 days. Periods run from 2000 onwards, up to 366 days, and can't end in the future (422). Rules: ADR-030.

| Method | Path | Requires | Description |
|---|---|---|---|
| GET | `/organizations/{id}/dashboard?start&end` | `report.view_organization` | Counts, on-time rate, daily trend, workload by department, `definitions`. |
| GET | `/organizations/{id}/reports/departments?start&end` | `report.view_department` somewhere | The departments you can report on, with their counts. |
| GET | `/organizations/{id}/departments/{dept}/dashboard?start&end` | `report.view_department` there | Adds by status, by assignee, and overdue, blocked and recent task lists (10 each). 403 for your own department without the permission, 404 for anyone else's. |
| GET | `/organizations/{id}/reports/members?start&end&page&page_size` | `report.view_organization` | Paginated, by name. |
| GET | `/organizations/{id}/members/{user}/summary?start&end` | yourself, or `report.view_department` in a department they belong to | 403 for a colleague you can see, 404 otherwise. |
| GET | `/organizations/{id}/reports/tasks.csv?start&end&department_id` | the matching report permission | Tasks open now or completed in the period. Up to 50,000 rows (422 `export_too_large`), 30 exports an hour (429). Recorded in the audit log. |

### Organizations (Phase 3)

All `/organizations/{id}/…` routes resolve an `OrgContext` from the URL plus an **active** membership. Anyone else (outsider, pending, suspended, removed) gets 404, so an organization's existence can't be probed. A member without the needed permission gets 403. All unsafe methods need CSRF.

| Method | Path | Requires | Description |
|---|---|---|---|
| GET | `/me/organizations` | session | Active organizations with `role_keys`, `permissions`, `department_permissions`, `department_ids`. |
| POST | `/organizations` | session | Create; caller becomes Owner in one transaction (with optional `departments`). |
| GET | `/organizations/discover?q=` | session | Opt-in organizations only, public fields + `my_status`. `q` ≥ 2 chars. |
| GET | `/organizations/{id}/join-info` | session | Public profile + open departments; 404 unless discoverable. |
| GET / PATCH | `/organizations/{id}` | member / `organization.settings.update` | Read / update profile and policies. |
| GET | `/organizations/{id}/departments` | member | Admins: all (`include_archived` optional). Others: their own only. |
| POST | `/organizations/{id}/departments` | `department.create` | 409 `department_name_taken`. |
| PATCH | `…/departments/{id}` | `department.update` (org or that department) | Edit. |
| POST | `…/departments/{id}/archive` · `/restore` | `department.update` | Archiving also closes join requests. |
| POST | `/organizations/{id}/membership-requests` | session | Discoverable orgs only. 409 `request_pending`, `already_member`, `member_suspended`; 422 department not open. Limit 20/h per user. |
| GET | `/me/membership-requests` · POST `/{id}/cancel` | session | The requester's own view. |
| GET | `/organizations/{id}/membership-requests?status=` | `member.approve` (any scope) | Department managers see their departments only. |
| POST | `…/membership-requests/{id}/approve` | `member.approve` for the target department; `role.assign` for non-Member roles | Body: `department_id` (amend), `role_key`. One transaction. Not `owner`. |
| POST | `…/membership-requests/{id}/reject` | `member.approve` | Optional `note`, shown to the requester. |
| GET | `/organizations/{id}/members?q=&department_id=&status=&page=` | `member.view` | Admins/approvers: everyone. Others: their departments. Each member carries `actions`, what the caller may do to them. |
| POST / GET | `/organizations/{id}/invitations` | `member.manage` (+ `role.assign` for non-Member) | `email` optional (omit for a shareable link), except for Admin invitations, which also last at most 7 days. `link` with the secret token is returned once only. Limit 50/h per user. |
| DELETE | `…/invitations/{id}` | `member.manage` | Revoke a pending invitation. |
| GET | `/invitations/{token}` · POST `/{token}/accept` | session | Preview / accept. Single-use. 400 `invitation_invalid`, which also covers a creator who has since lost the right to invite and an archived department; 403 `invitation_email_mismatch`; 409 `already_member`. |
| GET | `/organizations/{id}/audit-logs` | `organization.settings.update` | Paginated, read-only. |

### Member management (Phase 4)

`m` is a `membership_id`. Refusals: 404 for a member who isn't in this organization or was removed; 403 `forbidden` without the permission; 403 `owner_protected` when acting on the Owner; 403 `own_membership` for suspending, removing or re-roling yourself; 409 `member_state` when the member's status doesn't allow it. Rules: ADR-026.

| Method | Path | Requires | Description |
|---|---|---|---|
| GET | `/organizations/{id}/members/{m}/impact?action=&from_department_id=&to_department_id=` | as the action | Preview for `suspend`, `remove`, `transfer`, `leave_department`, including `tasks_to_reassign`. Applies the action's own checks and changes nothing. |
| PATCH | `…/members/{m}/roles` | `role.assign` | Body is the complete result: `organization_role` (`member`\|`admin`), `department_roles[]`. A department role needs membership of that department. |
| POST | `…/members/{m}/suspend` · `/remove` | `member.manage` | Optional `reason`, kept in the audit log. Remove answers 204. |
| POST | `…/members/{m}/reactivate` | `member.manage` | Roles and departments return as they were. |
| POST | `…/members/{m}/transfer` | `member.manage` | `from_department_id`, `to_department_id`. Roles limited to the old department end. 409 `already_in_department`. |
| POST / DELETE | `…/members/{m}/departments` · `/{department_id}` | `member.manage` | Add to, or take out of, a department. |
| POST | `/organizations/{id}/ownership-transfer` | Owner | `membership_id`, `password`. 204. 422 on a wrong password. Limit 10/h per user. |

### Organization tasks (Phase 5)

The shared `/tasks/{id}` routes work for both personal and organization tasks. Organization tasks carry `department`, `assignee`, `creator`, `collaborators`, `visibility`, `needs_reassignment`, plus `allowed_statuses` and `actions` saying what the caller may do. A task the caller can't see answers 404. Dates are local to the organization's timezone. Rules: ADR-027.

| Method | Path | Requires | Description |
|---|---|---|---|
| GET | `/organizations/{id}/tasks` | member | Visible tasks only. `view` = `team` \| `my_work` \| `collaborating` \| `archived`; filters `department_id`, `assignee`, `unassigned`, `creator`, `status`, `priority`, `tag`, `overdue`, `due_from`, `due_to`, `needs_reassignment`, `q`; `sort`. Search uses the same visibility rule as the list. |
| POST | `/organizations/{id}/tasks` | `task.create`, membership of the department | 201 `TaskDetail`. `department_id`, `assigned_to`, `collaborator_ids`, `visibility`, `visible_to`, `parent_task_id`. 404 for a department the caller isn't in. 422 for an archived department or an ineligible person. 403 for `organization` visibility without `task.view_all`. |
| GET | `…/departments/{id}/board` | department member or `task.view_all` | One column per status, up to 100 tasks each with `total`. Same filters. 404 otherwise, including for collaborators on one of its tasks. |
| GET / POST | `/organizations/{id}/tags` | member / `task.create` | Organization tags. 409 `tag_name_taken`. |
| PATCH / DELETE | `…/tags/{id}` | `organization.settings.update` | Edit or delete. |
| PATCH | `/tasks/{id}` | see ADR-027 | Also takes `assigned_to`, `department_id`, `visibility`, `visible_to` on organization tasks; 422 on personal tasks. |
| POST / DELETE | `/tasks/{id}/collaborators` · `/{user_id}` | creator or `task.manage_collaborators`; anyone can remove themselves | Returns `TaskDetail`. |
| DELETE | `/tasks/{id}` | — | 409 `archive_instead` on organization tasks. Subtasks can be deleted. |

### Collaboration and Inbox (Phase 6)

Each route checks access to the task on every call, so anything tied to a task is exactly as visible as the task. Someone who can't see it gets 404. Rules: ADR-029.

| Method | Path | Requires | Description |
|---|---|---|---|
| GET / POST | `/tasks/{id}/comments` | can view / `task.comment` | `body` up to 5,000 characters; `mention_user_ids` must be people who can see the task. Works on personal tasks, without mentions. 409 on archived tasks. |
| PATCH / DELETE | `/comments/{id}` | author; Owner or Admin may delete | Deleted comments keep their place, with `body` null. |
| GET | `/tasks/{id}/attachments` | can view | Files on the task. |
| POST | `/tasks/{id}/attachments?filename=` | can edit | The request body is the file itself, up to 10 MB. Type is decided from the file's contents. 422 `attachment_rejected`, 409 `too_many_attachments` (20 per task), 413. |
| GET | `/attachments/{id}/download` | can view, checked each time | Always downloads, never displays. |
| DELETE | `/attachments/{id}` | uploader, or who may archive the task | Removes the file too. |
| GET / POST | `/tasks/{id}/update-requests` | can view / `task.request_update` | `recipient_id` must be the assignee or a collaborator; optional `respond_by` date. 409 `update_request_pending`. |
| POST | `/update-requests/{id}/respond` | the recipient | `response_note`, optional `status`. 409 `update_request_closed`. |
| POST | `/update-requests/{id}/cancel` | the requester, or `task.request_update` | |
| GET | `/me/update-requests` | session | Requests waiting for you, on tasks you can still see. |
| GET | `/inbox?filter=` | session | `all`, `unread`, `assignments`, `update_requests`. A task you can't see comes back with `accessible: false` and no details. |
| GET | `/inbox/summary` | session | `unread`, `pending_update_requests`. |
| POST | `/notifications/{id}/read` · `/notifications/read-all` | session | Your own only. |

`UserRead` never includes password hashes, session tokens or internal flags. `TaskRead` includes server-computed `is_overdue` so every screen agrees on overdue state.

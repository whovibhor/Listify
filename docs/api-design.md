# WorkPulse — API Design

Conventions are defined in ADR-012. OpenAPI is generated by FastAPI at `/api/openapi.json` and browsable at `/api/docs` (disabled when `APP_ENV=production`).

## Conventions

- Base path: `/api/v1`.
- JSON only. Request and response bodies use dedicated Pydantic schemas, never ORM models.
- Authentication (from M1): HttpOnly session cookie `wp_session`; unsafe methods also require the `X-CSRF-Token` header matching the `wp_csrf` cookie (ADR-004, ADR-006).
- Every response carries `X-Request-ID` (accepted from the client if it is ≤ 64 chars of `[A-Za-z0-9_-]`, otherwise generated).
- Errors, for every non-2xx status:

  ```json
  { "error": { "code": "validation_error", "message": "Request validation failed",
               "details": [{ "field": "title", "message": "Field required" }],
               "request_id": "3f2c…" } }
  ```

  | Status | `code` | When |
  |---|---|---|
  | 400 | `bad_request` | malformed request not covered by validation |
  | 401 | `unauthenticated` | missing/expired session |
  | 403 | `forbidden` | resource visible but action not permitted, or CSRF failure |
  | 404 | `not_found` | missing **or not visible to the caller** (avoids cross-tenant existence leaks) |
  | 409 | `conflict` | uniqueness or state conflict |
  | 422 | `validation_error` | schema validation failed |
  | 429 | `rate_limited` | rate limit exceeded |
  | 500 | `internal_error` | unexpected; no internals exposed, details only in server log |
  | 503 | — | `/health` only, returns the health body with `status: "degraded"` |

- Pagination: `page` (1-based), `page_size` (default 25, max 100) → `{ "items": [], "page": 1, "page_size": 25, "total": 0 }`.
- Sorting: `sort=field,-other`. Filtering: explicit, documented query parameters per endpoint.
- Timestamps in responses are ISO 8601 UTC with `Z`.

## Endpoints

| Method | Path | Auth | Description | Milestone |
|---|---|---|---|---|
| GET | `/api/v1/health` | public | Service status; `checks.database` reflects a real `SELECT 1`. 200 when healthy, 503 when degraded. Exposes no hostnames, credentials or error text. | M0 ✅ |
| GET | `/api/v1/auth/csrf` | public | 204. Sets the `wp_csrf` cookie: random for visitors, re-derived from the session when signed in (self-repairing). | M1 ✅ |
| POST | `/api/v1/auth/register` | public + CSRF | 201 `UserRead`, signs in. 409 `email_taken`, 422 field errors (incl. password strength), 429. Rate limit: 10/h per IP. | M1 ✅ |
| POST | `/api/v1/auth/login` | public + CSRF | 200 `UserRead`, rotates the session. 401 `invalid_credentials` (same message for unknown email and wrong password), 429. Limits: 10/15 min per account, 50/15 min per IP. | M1 ✅ |
| POST | `/api/v1/auth/logout` | CSRF | 204, revokes the session server-side and clears cookies. | M1 ✅ |
| POST | `/api/v1/auth/password/forgot` | public + CSRF | 202 with a generic message whether or not the account exists; emails a single-use link (60 min). Limits: 10/h per IP, 3/h per account. | M1 ✅ |
| POST | `/api/v1/auth/password/reset` | public + CSRF | 204; sets the password, invalidates the token, revokes **all** sessions. 400 `invalid_token`, 422 weak password. Limit: 20/h per IP. | M1 ✅ |
| GET | `/api/v1/me` | session | Current user (`id, email, name, timezone, created_at`). | M1 ✅ |
| PATCH | `/api/v1/me` | session + CSRF | Update `name`, `timezone` (IANA). Unknown fields → 422. | M1 ✅ |
| POST | `/api/v1/me/password` | session + CSRF | 204; requires `current_password`; revokes the user's other sessions. Limit: 10/h per user. | M1 ✅ |
| GET | `/api/v1/me/sessions` | session | Active sessions with `current` flag. | M1 ✅ |
| DELETE | `/api/v1/me/sessions/{id}` | session + CSRF | 204; only the caller's own sessions (others → 404). | M1 ✅ |

| PATCH | `/api/v1/me/preferences` | session + CSRF | Save `theme` (`light` \| `dark` \| `system`) to the account; `GET /me` returns it as `theme`. | M2+ ✅ |
| GET | `/api/v1/me/tasks` | session | Paginated personal tasks (top-level only). `view` = `my_day` \| `all` \| `upcoming` \| `completed` \| `done_today` \| `archived`; filters `status`, `priority`, `tag` (repeatable), `overdue`, `q` (title, literal match); `sort` = `due`, `-due`, `priority`, `-priority`, `created`, `-created`, `title`, `completed`. | M2 ✅ |
| POST | `/api/v1/me/tasks` | session + CSRF | 201 `TaskDetail`. Dates are **local** to the user's timezone: `start_date`, `due_date`, optional `due_time` (omitted = all-day, i.e. end of that day). `parent_task_id` creates a subtask (one level, max 50). | M2 ✅ |
| GET | `/api/v1/tasks/{id}` | session | `TaskDetail` (incl. subtasks). 404 if not the caller's. | M2 ✅ |
| PATCH | `/api/v1/tasks/{id}` | session + CSRF | Partial update incl. `status` (validated, ADR-015) and `tag_ids`. 409 `invalid_transition`, `open_subtasks`, `task_archived`. | M2 ✅ |
| POST | `/api/v1/tasks/{id}/complete` · `/reopen` · `/archive` · `/restore` | session + CSRF | State actions; complete sets `completed_at`, reopen clears it (history kept). | M2 ✅ |
| DELETE | `/api/v1/tasks/{id}` | session + CSRF | 204; permanent for personal tasks (subtasks + history removed). | M2 ✅ |
| GET | `/api/v1/tasks/{id}/activity` | session | Newest-first history with actor name and before/after values (max 200). | M2 ✅ |
| GET / POST | `/api/v1/me/tags` | session (+ CSRF) | List / create personal tags (`name` unique per user, case-insensitive; `color` from a fixed palette). | M2 ✅ |
| PATCH / DELETE | `/api/v1/me/tags/{id}` | session + CSRF | Rename/recolor; delete detaches from tasks. | M2 ✅ |
| GET | `/api/v1/me/dashboard?period=7d\|30d\|90d` | session | Personal metrics with `definitions` (see ADR-022). | M2 ✅ |

`UserRead` never includes password hashes, session tokens or internal flags. `TaskRead` includes server-computed `is_overdue` so every screen agrees on overdue state.

Planned endpoints per milestone are listed in `implementation-roadmap.md` and will be added to this table with their authorization requirement as they are implemented.
